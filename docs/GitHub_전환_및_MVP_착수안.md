# GitHub 전환 및 MVP 착수안

작성일: 2026-11-06 KST
기준: SRS_기술설계서.md v1.2. 이 문서는 변경 제안이며 원본 명세의 구현 완료 상태를 변경하지 않는다.

## 확인된 현재 상태

- 작업 폴더에 SRS v1.2, requirements.tsv, compose.example.yaml, analysis-output.schema.json, 문서 정합성 점검 문서 및 검사 스크립트가 있다.
- 현재 폴더는 Git 저장소가 아니며 연결할 GitHub 저장소 주소는 아직 전달되지 않았다.
- 로컬 SDK 조회 결과 .NET SDK 9.0.314만 확인되었다. .NET 10 SDK 준비와 실제 빌드 검증이 필요하다.
- 기존 Compose 파일은 구현 전 설계 예시다. 실행 또는 NAS 배포 성공으로 취급하지 않는다.

## GitHub 전환 시 SRS 변경 제안

| 대상 | 수정 제안 |
|---|---|
| 1·2·5·15·19장, EXT의 SVN 관련 항목 | 개발 메인 저장소를 GitHub로 변경. Windows에서 Git으로 개발하고 운영 NAS는 승인된 산출물을 실행한다. SVN 이중 쓰기는 도입하지 않는다. |
| FR-035, 15장 | SVN 자동 커밋 계약을 Git 검증·PR 계약으로 대체. 작업 브랜치에서 변경하고 테스트·비밀 검사를 통과한 변경만 병합 대상으로 삼는다. 자동 병합·자동 배포를 기본값으로 두지 않는다. |
| NFR-001 | 소스뿐 아니라 Git 이력, PR, CI 로그·산출물, 컨테이너 이미지에 실제 키·토큰·계좌정보·비밀이 없어야 한다. 실제 응답 대신 합성 fixture만 사용한다. |
| NFR-009, 17·20장 | SVN revision 대신 전체 Git commit SHA, SDK 버전, NuGet lock, fixture hash, 테스트 결과 및 이미지 digest를 기록한다. |
| FR-036, MVP-12 | CI 검증과 운영 배포를 분리. 승인된 commit 및 이미지 digest를 배포 명세에 연결하고 migration·백업·롤백 증거를 남긴다. |
| T19 | 충돌, 테스트 실패, 합성 비밀 탐지, 검증 후 변경, push 실패를 시험한다. 실패 시 병합·배포가 진행되지 않고 로컬 변경이 보존되어야 한다. |
| POC-11 | GitHub 접근, 브랜치 보호 적용 가능 여부, 필수 CI 검사, 최소 권한, 실패 복구를 검증한다. 제공되지 않는 보호 기능은 대체 절차와 한계를 기록한다. |
| MVP-11 | verify.ps1 및 Git/PR 검증 흐름으로 변경. 검증은 배포를 호출하지 않으며 검증 대상 SHA와 결과를 묶는다. |
| requirements.tsv·부록 A·정합성 검사 | 본문 전환과 함께 같은 요구사항 ID의 문구·추적 항목·검사 규칙을 갱신한다. 기존 ID는 유지한다. |

### 브랜치·CI·보안 계약

- 기본 브랜치에서 짧은 작업 브랜치를 만들고 PR 단위로 검토한다. 실제 기본 브랜치명과 기존 규칙은 저장소 연결 후 확인한다.
- Windows/Linux에서 동일한 .NET 10 SDK와 잠긴 패키지로 복원·빌드·테스트한다. PostgreSQL 권한 시험은 실제 격리 DB에서 실행한다.
- CI는 기본 읽기 권한으로 시작한다. 외부 PR 코드에 운영 비밀을 전달하지 않는다. 외부 Action은 검증된 commit으로 고정한다.
- 실제 비밀을 사용하는 CI는 초기 MVP에 필요하지 않다. 테스트 DB 자격증명은 시험마다 생성하며 운영 자격증명을 재사용하지 않는다.
- .gitignore와 .dockerignore에 로컬 비밀·환경 파일·DB dump·실제 계좌 자료·로그를 제외한다. 제외 규칙만으로 보안을 보증하지 않고 커밋 전 검사와 CI 검사를 병행한다.
- 초기 CI에는 NAS 접근 키나 자동 배포 작업을 넣지 않는다. 운영 비밀은 저장소 밖에서 주입한다.

## MVP-01~04 구현·인수 범위

| 작업 | 구현 범위 | 검증 증거 |
|---|---|---|
| MVP-01 | .NET 10 solution, Worker CLI, global.json, NuGet lock, 비밀 없는 설정 예시, README, CI | Windows/Linux 빌드·테스트 결과. Fake 모드는 실제 키 없이 실행. 외부 연결 구성 누락은 명확한 실패로 처리. |
| MVP-02 | owner와 인증 principal 분리, account/instrument/quality 모델, decimal, UTC DateTimeOffset | 계좌 중복·owner 불일치·통화/시장·UTC 계약 fixture 및 기본 거부 권한 시험. |
| MVP-03 | PostgreSQL migration, 제한 역할, grant/consent, RLS, audit | T01/T04 관련 범위: 타명의 접근, 위조 owner, 만료·철회 grant, 연결 풀 재사용, 복합 FK 불일치 시험. 앱 DB 역할에 소유자·superuser·BYPASSRLS 권한이 없어야 한다. |
| MVP-04 | 주문 메서드 없는 IReadOnlyBroker와 Fake adapter, 합성 fixture | 정상, 여러 페이지, 401, 429, timeout, 중간 페이지 실패 및 취소 재현. 실제 네트워크 호출 없이 실행. |

MVP-03의 시험 통과는 전체 제품의 T04 완료를 의미하지 않는다. API·캐시·알림·분석 입력 권한 시험은 해당 기능 구현 때 추가한다. 전체 페이지의 원자 저장은 MVP-05, 토큰 갱신·limiter·retry는 MVP-06 범위다.

## 유지할 범위와 착수 조건

- 초기 제품은 조회·분석·알림 전용이다. 주문 인터페이스, 실행 코드, 주문 자격증명 및 주문 컨테이너를 포함하지 않는다.
- 외부 텔레그램 채널 수신은 후순위다. 기존 Telegram 알림 발송 요구사항 FR-029/030과 P5 계획은 유지한다.
- 사용자 GitHub 저장소 주소를 받은 뒤 해당 저장소의 기존 파일·작업 규칙을 확인하고 구현을 시작한다. 주소 추정이나 별도 원격 저장소 생성은 하지 않는다.
- SDK·패키지·컨테이너 버전은 구현 시 공식 배포 정보와 호환성을 확인해 고정한다.
- 현재 MVP-01~04는 미착수이며 빌드·DB 시험·CI·NAS 배포는 실행하지 않았다.
